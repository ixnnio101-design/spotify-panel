АУДИТ SPOTIFY PANEL — история изменений и проверка 6 ноября 2026

Историческая база разделов ниже: проект FIXED v3. Дополнительно полностью просмотрена структура исходников v7 и проверена интеграция новой модели и поиска (6 ноября 2026).

ИСПРАВЛЕНО В ЭТОМ АРХИВЕ
1. WorldPanel больше не создаёт новый большой BufferedImage 768x500 при каждом обновлении текстуры. Полотно и промежуточные изображения обложек переиспользуются; перед новой отрисовкой полотно очищается, чтобы не оставались следы предыдущего кадра.
2. Колёсико мыши больше не должно перехватываться панелью, когда она скрыта, мир не загружен или открыто не окно чата. В остальных случаях событие передаётся предыдущему обработчику Minecraft.
3. Таблица отображает пять полностью помещающихся строк вместо шести частично обрезанных.
4. Ошибка чтения треков Spotify больше не стирается пустым результатом. При ошибке HTTP (в том числе 403/429) сохраняется понятное сообщение; уже успешно загруженные страницы остаются видимыми.
5. Добавлена общая пауза API-запросов по заголовку Retry-After при HTTP 429. Во время паузы мод не продолжает долбить Spotify запросами; последнее известное состояние воспроизведения не очищается только из-за паузы.
6. OAuth-запрос получения/обновления токена теперь имеет тайм-аут 10 секунд.
7. Ошибки чтения и сохранения spotifypanel.json теперь пишутся в лог вместо полного молчания.
8. Версия Fabric Loom зафиксирована на 1.19.3 — именно эту версию показывал предыдущий успешный этап конфигурации GitHub Actions. Это уменьшает риск случайного изменения сборки из-за SNAPSHOT.
9. README и список изменений обновлены, чтобы не противоречить текущему поведению запуска разделов медиатеки.


ДОПОЛНИТЕЛЬНОЕ ИСПРАВЛЕНИЕ ПО СКРИНШОТУ (5 ноября 2026)
9. Убрано оптимистическое присваивание нажатой строки в Snapshot до подтверждения от Spotify. Раньше панель могла сразу показать нажатую песню как «Сейчас играет» и подсветить её, даже если Spotify фактически продолжал воспроизводить другую композицию или отклонил команду. Теперь подпись, обложка, прогресс и зелёная подсветка опираются на подтверждённое состояние плеера из Spotify API.
10. URI текущего трека для подсветки стабилизируется: новое непустое значение принимается после 300 мс, пустое состояние — только если сохраняется 2,5 секунды. Это предотвращает краткое мигание подсветки из-за промежуточных пустых ответов при смене трека.
11. Если список треков выбранного раздела временно перезагружается (items == null), анимация текущей подсветки ставится на паузу вместо сброса. Когда список снова доступен, подсветка сопоставляется по точному URI.

ОСТАВШИЕСЯ РИСКИ / ОГРАНИЧЕНИЯ
- Кэши содержимого плейлистов и обложек пока не имеют жёсткого ограничения по размеру. При очень долгой сессии с большим количеством разных разделов они могут постепенно занимать больше памяти. Обычная краткая сессия от этого не должна страдать; внедрение LRU-кэша требует отдельной проверки, чтобы не вызывать повторную загрузку обложек при прокрутке.
- Spotify опрашивается примерно раз в 2 секунды. При частом использовании других запросов это расходует квоту API; теперь на 429 применяется Retry-After, но более редкий опрос можно рассмотреть отдельно.
- Spotify Web API может запрещать чтение элементов плейлиста, если пользователь не владелец и не соавтор (403). Также запуск воспроизведения через Player API требует Spotify Premium. Это ограничения Spotify, а не ошибки рендеринга Minecraft.
- PanelRenderer — старый HUD-рендерер, который сейчас отключён условием WorldPanel.ENABLED. Он остаётся в исходниках и практически не выполняет работу; текущая панель рисуется через WorldPanel.
- Refresh token хранится в spotifypanel.json в конфигурационной папке Minecraft. Не публикуй этот файл и не отправляй его вместе с логами/архивом.

ПРОВЕРКИ, ВЫПОЛНЕННЫЕ В ЭТОЙ СРЕДЕ
- Все 8 Java-файлов разобраны компилятором JDK 21 через JavacTask.parse(): синтаксических ошибок не найдено.
- JSON в fabric.mod.json и Blockbench-модели panel.bbmodel успешно разобран.

ДОПОЛНИТЕЛЬНАЯ ПРОВЕРКА МОДЕЛИ И ПОИСКА (6 ноября 2026)

Структура проекта
- Точка входа: `SpotifyPanelMod.onInitializeClient()` загружает конфигурацию, создаёт `SpotifyAuth` и `SpotifyClient`, запускает API-опрос, регистрирует команды и `WorldPanel`.
- `WorldPanel` — активная мировая панель: импортирует `panel.bbmodel`, строит плоскую геометрию, рисует динамический слой и обрабатывает клики/колёсико. `PanelRenderer` остаётся старым HUD-рендерером и не является основным способом отображения панели.
- `SpotifyClient` отвечает за Spotify Web API, медиатеку, состояние воспроизведения и очереди команд. Поиск использует существующий HTTP-клиент и выделенный пул фоновых запросов.
- `SpotifyAuth` сохраняет прежний набор OAuth-разрешений; отдельный scope для поиска не добавлялся.

Изменения
- Ресурс `panel.bbmodel` заменён точным содержимым присланного файла: 14 элементов, включая `search_corpus`. Все элементы модели остаются плоскими и не имеют вращения, что соответствует возможностям текущего импортёра.
- Масштаб и координаты динамического слоя, боковой медиатеки, списка треков, текущего трека и нижних контролов обновлены для габаритов модели 22 × 14,4. Геометрия интерактивных областей сопоставлена с новыми элементами.
- Добавлен ввод Unicode в корпус поиска, Backspace/Delete, очистка Ctrl+A, снятие фокуса Enter/Esc и возврат клавиатуры Minecraft после снятия фокуса.
- Поиск запускается после 320 мс паузы, выполняется асинхронно. Номер поколения запроса не позволяет старому ответу заменить результаты более нового запроса.
- Результаты отображаются в центральном списке; колесо прокручивает выдачу, щелчок по треку запускает его через альбомный контекст, если Spotify вернул URI альбома. Очередь избранного при этом сбрасывается, чтобы следующий/предыдущий трек не оставался привязан к прежнему списку лайков.

Проверки этой версии
- Все 8 Java-файлов успешно прошли синтаксический разбор компилятором JDK 21 (`JavacTask.parse`), ошибок синтаксиса не найдено. Это не заменяет полноценную компиляцию с зависимостями.
- `fabric.mod.json` и новая `panel.bbmodel` успешно разобраны как JSON.
- В модели ровно 14 элементов; ресурсная копия совпадает с загруженным `.bbmodel` побайтно; координаты `search_corpus` проверены.
- Gradle намеренно не запускался по просьбе пользователя. ZIP содержит исходники и ресурсы проекта, а не собранный JAR.

УЛУЧШЕНИЕ ЧИТАЕМОСТИ 3D-ПАНЕЛИ (14 ноября 2026)
- Логическая сетка интерфейса сохранена 768×500, но буфер динамического оверлея увеличен до 1536×1000. Все текущие размеры шрифтов, отступы, иконки и контролы остаются прежними в мировом масштабе; выросла только плотность исходной растеризации.
- Java2D продолжает использовать сглаживание текста и фигур; дополнительно включены качественная интерполяция цветов/альфа-канала и точное управление штрихами.
- Динамическая текстура получила линейную фильтрацию, CLAMP_TO_EDGE и аппаратную анизотропию до 4× с учётом возможностей GPU. Самплер освобождается вместе с текстурой.
- Формулы преобразования UV в указатель и координаты отрисовки `px/py` работают в логических 768×500 единицах. Клики, прокрутка, поиск, перемотка и громкость не перенастраивались.
- Геометрия `panel.bbmodel`, мировая привязка, размеры плоскости и UV-координаты 3D-оверлея не изменялись. Панель остаётся в мире Minecraft и сохраняет перспективу.
- Внутренняя текстура стала в 4 раза больше по числу пикселей (2× по каждой стороне), что увеличивает расход видеопамяти и стоимость обновления оверлея; масштаб ограничен 2×, чтобы не создавать чрезмерную нагрузку.
- Gradle не запускался. Выполнен синтаксический разбор Java и проверена целостность ZIP.



ОПТИМИЗАЦИЯ ПОСЛЕ ПРОБЛЕМЫ С FPS (14 ноября 2026)
- Уменьшен коэффициент supersampling с 2.0 до 1.5: размер оверлея теперь 1152×750 вместо 1536×1000.
- Вместо миллиона вызовов `NativeImage.setColorArgb` используется переиспользуемый direct ByteBuffer и публичный `CommandEncoder.writeToTexture(GpuTexture, ByteBuffer, NativeImage.Format, ...)` API Minecraft 1.21.11. Пиксели Java2D конвертируются ARGB → RGBA в буфер; GPU получает весь кадр одним bulk-upload вызовом.
- Частота обновления именно динамической текстуры: 24 FPS при кликах/перетаскивании/анимации/поиске; 15 FPS во время воспроизведения; 2 FPS в статичном простое. Геометрия и world-space quad по-прежнему рендерятся обычным игровым FPS.
- Ограничена анизотропия до 2×, линейная фильтрация оставлена; Java2D использует bilinear interpolation при масштабировании обложек.
- Проверить реальную нагрузку и визуальное соответствие GPU upload нужно в игре на целевой видеокарте: среда подготовки не запускает Minecraft. Gradle не запускался.


ЧАСТИЧНЫЙ РЕНДЕРИНГ ДИНАМИЧЕСКИХ ОБЛАСТЕЙ (14 ноября 2026)
- Исправлена архитектура обновления текстуры: ранее при каждом ограниченном по FPS обновлении вызывался paintOverlay(), очищавший и заново рисовавший весь холст 1152×750, после чего выполнялся полный upload.
- Теперь полный paintOverlay()/upload используется только при первом создании текстуры и повторном открытии панели. OVERLAY_IMAGE сохраняется между кадрами; изменённые элементы перерисовываются через clip только внутри собственного dirty-региона.
- Обновление шкалы/таймера проигрывания ограничено нижним центральным прямоугольником; громкость — собственным нижним правым прямоугольником; play/pause — областью центральной кнопки; метаданные трека — левым блоком нижней панели; сведения о текущем треке — правой колонкой; статус воспроизведения — отдельной строкой.
- Подсветка активного трека обновляет только таблицу и только пока изменяется alpha перехода; стабильная подсветка не вызывает повторных загрузок. Изменение прокрутки обновляет только боковую медиатеку или таблицу/результаты поиска.
- При смене выбранного раздела, списка, режима поиска или результатов обновляется только основной контентный регион; полный экранный холст не очищается.
- uploadRegion() конвертирует только пиксели dirty-региона и использует CommandEncoder.writeToTexture с offsetX/offsetY для записи подпрямоугольника GPU-текстуры. Сигнатура метода соответствует API Minecraft 1.21.11 (mipLevel, depth, offsetX, offsetY, width, height).
- Проверены границы dirty-регионов в логических координатах 768×500: все лежат внутри текстуры, зоны прогресса, центральной кнопки и громкости не накладываются друг на друга; начальный full-render остаётся резервным сценарием и выполняется при повторном открытии.
- Все 8 Java-файлов прошли синтаксический разбор JDK 21; fabric.mod.json и panel.bbmodel разобраны как JSON. Gradle и Minecraft не запускались, поэтому визуальные артефакты и FPS на реальной видеокарте требуют проверки в игре.
